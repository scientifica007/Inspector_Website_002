# المعمارية والصلاحيات

## الفصل بين الكيانات

| الكيان | وظيفته | ما يبقى مستقلًا عنه |
|---|---|---|
| Reference / ReferenceNode | مكتبة قابلة للتحرير بهويات UUID مستقرة | لقطات الزيارات والاقتراحات المرسلة |
| Visit / VisitNode | حدث فعلي ونسخة شجرة خاصة به | المرجع الحي |
| Guide | اقتراح أهداف مرتبط بمرجع مشترك | تطبيقاته السابقة |
| GuideApplication | مادة الدليل عند تطبيقه وبصمة وتقرير إضافة/تخطٍّ | تعديل الدليل أو حذفه |
| Assignment / Entry / Obligation | تكليف وقيود لكل هدف ولكل عقدة موسعة | أصل العنصر والقيود الأساسية |
| Submission | نسخة مرجع شخصي أرسلها مالكها للمراجعة | التحرير اللاحق للمصدر وحذفه |

الشجرة تسمح بفرع تحت فرع، ووصف تحت فرع، وبند تحت فرع أو وصف. يمكن إنشاء عناصر رئيسية من أي نوع.
الأب يجب أن ينتمي إلى المرجع نفسه. يمنع الدوران، ويمنع وضع أبناء تحت بند، ويمنع تغيير نوع عقدة لها أبناء.
الترتيب `position` ثم UUID يضمن استقرار ترتيب العناصر المتساوية؛ تعديل الترتيب لا يغير الهوية.

## طبقات التنفيذ

`HTTP -> authentication/authorization -> Django Form -> service -> transaction -> ORM/database guards`.
الواجهة تعرض الحالة فقط؛ إخفاء زر ليس حاجز الصلاحية. خدمات الكتابة تعيد فحص صاحب الزيارة وحالتها داخل المعاملة.
عمليات التكليف تقفل الزيارة أولًا ثم التكليف. PostgreSQL يستخدم `select_for_update`، وSQLite معاملات `IMMEDIATE`
مع مهلة 30 ثانية لتسلسل الكتّاب. لم يُجرَ اختبار حمل أو محاكاة ضغط متعدد العمليات؛ نجاح CI ليس ادعاءً للأداء تحت الضغط.

## النطاق والحقيقة التاريخية

إنشاء الزيارة ينسخ هوية المؤسسة والمفتش ومادة المرجع، ويُنشئ VisitNodes لجميع عناصره بحالة غير مختارة.
لا توجد علاقة FK من الزيارة إلى المرجع؛ حذف المصدر لا يتبع الزيارة. UUID المصدر يبقى معلومة تاريخية.

- `SELECTED`: اختاره المفتش أو أُدخل بدليل/تكليف/محتوى محلي.
- `CONTEXT`: سلف ضروري لفهم عنصر مختار، لكنه ليس متطلب تنفيذ.
- `AVAILABLE`: موجود في اللقطة، خارج النطاق والسياق الحاليين.
- `ACTIVE / EXCLUDED`: حالة العنصر المختار. الاستبعاد لا يمس القيمة أو النتيجة أو الملاحظة.

الأصل يسجل عند الإدخال الأول: `MANUAL / GUIDE / ASSIGNMENT / LOCAL`، ويُحفظ `LEGACY` لاستيرادات مستقبلية؛
لا يوجد استيراد بيانات قديمة في هذه النسخة. وجود قيمة LEGACY لا يدعي وجود migration من مشروع سابق.
عقد السياق والعقد المتاحة قد تحمل origin فارغًا لأنها لم تُختَر قط. لا يفرض النظام أي visit mode عام.

التقدم = الأوصاف التي لها قيمة غير فارغة + البنود ذات نتيجة صالحة، مقسومًا على الأوصاف والبنود النشطة المختارة.
الفروع والسياق والعناصر المستبعدة لا تدخل المقام. عند المقام صفر يظهر `0 / 0` و`0%`، لا إنجاز افتراضي 100%.

## الأدلة والتكليفات

دليل متوافق يعني أن هويته المرجعية تطابق هوية المرجع الذي أُنشئت منه الزيارة. تُفسَّر الأهداف داخل لقطة الزيارة فقط.
الهدف المفقود يسجل في `skipped`. التوسع في الفرع يتم في شجرة الزيارة، دون قراءة أبناء المرجع الحي.
بصمة المادة المطبقة + هوية الزيارة + هوية الدليل فريدة. إعادة تطبيق النسخة نفسها لا تكرر العناصر ولا تعكس استبعادًا لاحقًا.
تطبيق نسخة معدلة فعل جديد صريح يسجل منفصلًا؛ ولا يُعاد تطبيقها تلقائيًا.

الإصدار يتحقق من جميع أهداف التكليف ومن القيود أولًا، ثم ينشئ التزامات ويختار العناصر ضمن معاملة واحدة.
لا تستهدف التكليفات عناصر محلية أو معرّفات خارج JSON المرجع المجمد. قيد الفرع يُوسع إلى عناصر المرجع المجمدة عند الإصدار؛
المحتوى المحلي اللاحق لا يصبح إلزاميًا خلسة. تثبيت فرع يحمي أبناءه، وتثبيت بند لا يمكن تجاوزه باستبعاد سلفه.

`effective.scope_locked = baseline_scope_locked OR any(issued scope lock)`، وينطبق المنطق نفسه على `completion_required`.
كل Obligation يحتفظ بمرجعه إلى Entry وتكليفه. إلغاء تكليف يغير حالته فقط، فلا تُمحى الالتزامات التاريخية ولا بيانات التنفيذ.
العناصر التي أضافها التكليف تبقى في النطاق بعد إلغائه؛ يستطيع المفتش استبعادها إذا لم يعد عليها قيد.

## الإكمال

يفحص الإكمال كل requirement فعال: يجب أن يكون العنصر مختارًا ونشطًا ومنجزًا.
يمكن استبعاد عنصر مطلوب غير مثبت أثناء المسودة، لكن الاستبعاد لا يتحايل على شرط الإكمال.
العناصر غير الإلزامية يمكن أن تبقى دون نتيجة. مسودات التكليفات الإدارية المخفية لا تمنع المفتش من الإكمال.

يحفظ `completed_payload` في المعاملة نفسها التي تحول الحالة إلى COMPLETED. التصدير بعد ذلك يعيد هذه المادة المختومة.
Migration `0002_history_guards` تمنع UPDATE/DELETE للزيارة المكتملة، وINSERT/UPDATE/DELETE لعقدها والتكليفات
ومدخلاتها والتزاماتها وتطبيقات الأدلة، وتحمي مادة المرجع المجمدة وأصل العنصر ومادة الاقتراح حتى أثناء المسودة.
هذه حماية إضافية ضد أخطاء ORM؛ الخدمات هي واجهة الكتابة المقصودة. لا يُعرّض Django Admin عامًا يستطيع تجاوزها.

## مصفوفة الصلاحيات

| العملية | صاحب الزيارة / المفتش | مفتش آخر | الإدارة |
|---|---|---|---|
| قراءة مرجع مشترك | نعم | نعم | نعم |
| تحرير مرجع مشترك | لا | لا | نعم |
| قراءة/تحرير مرجع شخصي | المالك فقط | لا | فقط إذا كانت تملكه |
| مراجعة مادة مرجع مرسل | المرسل يقرأ | لا | تقرأ وتقبل أو ترفض |
| إنشاء زيارة | نعم | ينشئ زياراته | يمكنها إنشاء زياراتها |
| قراءة زيارة/تصديرها | نعم | لا | نعم ضمن المراجعة الإدارية |
| نطاق/نتائج مسودة | المالك فقط | لا | لا لمسودة غير مملوكة |
| حذف مسودة | المالك فقط | لا | لا لمسودة غير مملوكة |
| إنشاء/إصدار/إلغاء تكليف | لا | لا | نعم داخل DRAFT فقط |
| قراءة تكليف إداري DRAFT | لا | لا | نعم |
| تغيير/حذف زيارة مكتملة | لا | لا | لا |

التعطيل بدل حذف مؤسسة مستخدمة. حذف مرجع يحذف شجرته وأدلته الحية، ولا يحذف لقطات الزيارات أو الاقتراحات أو تطبيقات الأدلة.
حذف مسودة زيارة بعد تأكيد صاحبها يحذف محتواها وسجل تكليفاتها معها؛ لا توجد صلاحية حذف عامة للإدارة ولا زر استرجاع للمسودة.
قبول اقتراح ينشئ مرجعًا مشتركًا مستقلًا بمعرّفات جديدة و`stable_id_map` في provenance؛ لا ينقل ملكية المرجع الشخصي.

## التشغيل والحدود

لا اعتماد على Seed للتشغيل. لا بيانات حقيقية في Git. لا offline sync أو ملفّات مرفقة أو إرسال بريد أو تكاملات خارجية.
النشر على خادم Django تقليدي موثق في README. استخدام Sites اقتصر على إرشادات الواجهة ومعاينة التخطيط؛ لم يسجل Site بديل.
أدوات QA تولد HTML حقيقيًا بواسطة Django Test Client مع بيانات وهمية؛ لا تثبّت تجاوز مصادقة داخل تطبيق الإنتاج.
