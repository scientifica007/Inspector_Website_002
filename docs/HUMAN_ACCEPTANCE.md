# بروتوكول القبول البشري

**الحالة: Pending.** النجاح الآلي لا يساوي اعتماد المنتج نهائيًا. يمكن تنفيذ الاختبار الحر، وتُربط أدلته بهذه الحالات دون تكرار غير لازم.
استخدم قاعدة تجريبية منفصلة وحسابي إدارة ومفتش، وأضف مفتشًا ثانيًا لاختبار الملكية. أثبت SHA المختبَر والمتصفح والجهاز.

| ID | السيناريو | معيار القبول |
|---|---|---|
| HA-01 | الدخول والخروج | كلمة خاطئة مرفوضة، صحيحة تفتح الحساب الصحيح، والخروج ينهي الجلسة |
| HA-02 | الحاسوب وRTL | التنقل والقراءة والتاريخ يوم/شهر/سنة واضحة، والنص الطويل لا يغطي الأزرار |
| HA-03 | هاتف عمودي وأفقي | افتح النطاق والتنفيذ والأدلة والتكليفات، وجرب القائمة واللمس والكتابة والحفظ؛ لا تجاوز أفقي غير لازم |
| HA-04 | المؤسسات | الإدارة تنشئ/تعدل/تعطل مؤسسة؛ المفتش يختار النشطة ولا يستطيع إدارة المؤسسات عبر رابط مباشر |
| HA-05 | المراجع المستقلة | أنشئ مرجعين مشتركين؛ وجود الثاني لا يلغي الأول؛ أضف فرعًا ووصفًا وبندًا وحرر الترتيب |
| HA-06 | المرجع الشخصي | أنشئ مرجعًا كمفتش؛ الحساب الثاني والإدارة لا يريان المصدر الشخصي غير المرسل |
| HA-07 | الإرسال والرفض | أرسل المرجع، عدّل المصدر، اقرأ النسخة المرسلة بالإدارة؛ تبقى قديمة. ارفض؛ يبقى المصدر شخصيًا |
| HA-08 | القبول | أرسل نسخة أخرى واقبلها؛ يظهر مرجع مشترك مستقل، ويبقى الشخصي وملكيته |
| HA-09 | إنشاء الزيارة | المؤسسة والتاريخ والمرجع صحيحة؛ النطاق فارغ رغم وجود شجرة مجمدة متاحة |
| HA-10 | اختيار بند عميق | أضف بندًا واحدًا تحت وصف وفرع؛ يظهر الأسلاف «سياق فقط» ويكون المقام 1 |
| HA-11 | اختيار فرع/وصف | أضف فرعًا أو وصفًا؛ يدخل أبناؤه، ولا يتكرر البند الذي سبق اختياره |
| HA-12 | المحتوى المحلي | أضف فرعًا ووصفًا وبندًا محليًا، ثم حرر النص؛ لا تظهر إضافة تلقائية بمقترحات التعميم |
| HA-13 | التنفيذ والاستبعاد | سجل «غير مطابق» وملاحظة، استبعد ثم استرجع؛ تبقى البيانات وتنخفض/ترتفع أعداد التقدم بصورة صحيحة |
| HA-14 | الدليل الاختياري | طبقه صراحة؛ الأصل السابق يبقى، والجديد GUIDE؛ لا قيد ولا إلزام. كرر التطبيق؛ لا ازدواج ولا تراجع عن استبعاد لاحق |
| HA-15 | الفارق الزمني | أنشئ زيارة ثم أضف هدفًا للمرجع والدليل؛ التطبيق القديم يتخطاه بوضوح ولا يسحب المحتوى الجديد |
| HA-16 | حذف/تغيير المصدر والدليل | صدّر مسودة، ثم عدل/احذف المصدر أو الدليل؛ لا تتغير عقدها أو المادة المطبقة |
| HA-17 | التكليف في مرحلتين | أنشئ مسودة تكليف بالإدارة؛ لا تظهر للمفتش. أصدرها؛ تظهر قيودها كاملة |
| HA-18 | تثبيت النطاق | ثبّت فرعًا وبندًا؛ استبعاد البند أو التحايل باستبعاد أحد أسلافه يرفض دون فقد بيانات |
| HA-19 | اشتراط الإنجاز | اطلب إنجاز بند دون تثبيت؛ يمكن استبعاده لكن لا إكمال قبل استرجاعه وإنجازه؛ الفرع الهيكلي لا يُطلب كقيمة |
| HA-20 | تداخل التكليفات | A يثبت بندًا وB يطلب إنجازه؛ ألغِ A بتعليل؛ يزول تثبيته ويبقى شرط B |
| HA-21 | الإلغاء | السبب إلزامي؛ يسجل الشخص والوقت والسبب؛ لا تُحذف النتائج ولا تُستبعد العناصر تلقائيًا |
| HA-22 | الإكمال والحماية | أكمل بعد استيفاء الإلزام؛ لا تحرير نتائج أو نطاق، لا حذف، لا إصدار أو إلغاء تكليف بعدها |
| HA-23 | التصدير | نزّل JSON مرتين دون تعديل؛ الملفان متطابقان. افحص selected/context/excluded/origin/baseline/effective وسجل الإلغاء |
| HA-24 | ملكية المسودة | المالك يحذف DRAFT بعد تأكيد؛ المفتش الآخر والإدارة لا يحذفان مسودته |
| HA-25 | ثبات الماضي | بعد إكمال زيارة عدّل المرجع والدليل وأسماء المؤسسة؛ ملف الزيارة المكتملة لا يتغير |

القيود الأصلية واختبار إصدار تكليف يحوي هدفًا فاسدًا متعمدًا مغطاة آليًا؛ لا توجد واجهة لإنشاء بيانات فاسدة أو تعديل baseline
في هذه النسخة. لا يُطلب من المستخدم العبث بقاعدة البيانات لإعادة هذه الاختبارات.

## تصنيف أدلة الاختبار الحر

| التصنيف | متى يستخدم |
|---|---|
| PASS | دليل بشري واضح يثبت السلوك المتوقع عند SHA معلوم |
| TECHNICAL-PASS | الاختبار الآلي/المحاكاة يثبت النطاق المحدد، ويظل الحكم الميداني البشري منفصلًا |
| RETEST | تغير الكود المرتبط أو كان الاختبار السابق قبل الإصلاح؛ حدد السبب |
| DEFECT | عيب قابل للوصف والتكرار مع المتوقع والفعلي |
| UNCERTAIN | الدليل لا يحسم النتيجة؛ اطلب أقل معلومة ناقصة |

سجل الدليل: `ID، SHA، الحساب/الدور، الجهاز/المتصفح، الخطوات، المتوقع، الفعلي، صورة أو JSON إن لزم، التصنيف`.
اربط الاختبار الحر بكل IDs التي يغطيها، ثم اطلب فقط ما بقي غير مغطى. لا تعِد حالة PASS دون تغيير مرتبط أو تناقض واضح.
لا تضع أسماء حقيقية أو تقارير تفتيش فعلية في GitHub العام؛ استخدم أمثلة منزوعة البيانات الشخصية.
